# 种子集标注方案 v0.1

> 目标：产出 200-500 篇人工标注的 gold set，用于（a）多模型抽取性能评测与选型，（b）后续可能的少样本提示/微调。
> 前置阅读：`event_ontology.md`（本体 v0.1，同目录）。标注与本体版本绑定。

## 1. 抽样策略（分层抽样）

从 documents 表按三个维度分层，保证 gold set 覆盖多样性：

| 维度 | 分层 | 每层占比目标 |
|---|---|---|
| 信源 | ndrc / nea / gzpec / nmg（及未来新增） | 按库内比例，nea/gzpec 等小信源至少保底 10 篇 |
| 年份 | 2021 及以前 / 2022-2023 / 2024 / 2025 / 2026 | 向近年倾斜（2024 后 ≥60%），早期政策保证 ≥15% |
| 关键词命中类型 | 绿证 / 消纳权重 / 绿电交易 / 绿电消费 等 | 每类至少 20 篇，避免"全是绿证标题"的单一分布 |

**规模**：pilot 200 篇 → 视一致性情况扩到 500 篇。当前库 156 条且每日增长，pilot 可先按库内容量全量标注重点文档 + 抽样其余。

抽样脚本（待写）：`src/sample_seed.py`，从 SQLite 读出候选、按分层配额抽样、导出 JSONL 待标注文件。

## 2. 标注格式

每篇文档一行 JSONL：

```json
{
  "doc_id": 123,
  "source": "ndrc",
  "title": "...",
  "annotator": "A",
  "ontology_version": "0.1",
  "events": [
    {
      "event_type": "C",
      "subtype": "C1",
      "actor": "国家发展改革委",
      "object": "各省",
      "strength": "约束性",
      "effective_date": "2026-01",
      "region": "全国",
      "industry": ["数据中心", "钢铁"],
      "price_direction_prior": "上行",
      "evidence_span": "……原文片段……"
    }
  ]
}
```

无事件文档标注 `"events": []`（负样本同样重要，防止模型过度抽取）。

## 3. 标注流程与质量控制

1. **标注员培训**：先共同标注 20 篇，逐条对答案、修订本体边界规则（本体升 v0.2）
2. **双人独立标注**：随机 20% 子集（40 篇）两人背靠背标注
3. **一致性检验**：
   - event_type 级别：Cohen's kappa ≥ 0.75 达标
   - 字段级 F1（按 evidence_span 对齐配对后逐字段算）：≥ 0.80 达标
   - 不达标 → 回到第 1 步修本体，重标
4. **分歧仲裁**：第三人（建议导师或你）裁决双人不一致样本，裁决结果作为 gold 标签
5. **单人标注剩余 80%**，标注员每周抽 10% 自查

## 4. 工具

- 首选 **Label Studio**（本地 docker/pip 部署，免费）：支持 JSON 导入导出、双人标注、预标注（可先让 LLM 预标，人工只修正——预计省 60% 工时）
- 备选：直接标 JSONL + VS Code，配一个校验脚本 `src/validate_annotation.py`（检查 schema、枚举值、日期格式）

## 5. 与多模型评测的衔接（回答"单模型还是多模型"）

gold set 建成后按两阶段使用：

| 阶段 | 做法 | 产出 |
|---|---|---|
| 评测阶段 | 3 个候选模型（DeepSeek-V3 / Qwen-Max / GPT-4o 级）在 gold set 上跑相同 prompt，按字段级 F1 + 单篇成本对比 | 模型选型表（质量-成本权衡）→ 进论文实验节 |
| 生产阶段 | 选型胜出的**单模型**批量抽取全部语料 | events 表 |
| 鲁棒性 | 高价值文档（B/C/D 类约束性事件）用第二模型交叉验证，不一致样本人工复核 | 论文鲁棒性证据 |

## 6. 里程碑建议

- 第 1 周：标注工具部署 + 20 篇培训标注 + 本体 v0.2
- 第 2-3 周：双人标注 40 篇 + 一致性检验
- 第 4-6 周：单人标注至 200 篇 → gold set v1 冻结
- 之后：多模型评测 → 选型 → 批量抽取
